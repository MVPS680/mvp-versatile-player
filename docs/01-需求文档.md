## 1. 一句话概括

**在 Windows 上双击就能放着不管的播放器**：常见音视频格式全都能放、中文外挂字幕不乱码、
图片也能看、和资源管理器是一家人、开得快、关得也快，而且**不需要管理员权限**。

---

## 2. 背景：为什么还要再做一个播放器

### 2.1 现状

| 现状 | 具体表现 |
|---|---|
| 系统自带的播放能力在退化 | Windows 自带的"电影和电视"/媒体播放器对容器格式、编码格式和外挂字幕的支持都很有限，常见素材直接提示"无法播放"，或者要求去应用商店装付费扩展 |
| 第三方播放器"功能多但体验重" | 设置项动辄成百上千、界面与中文用户的使用习惯有落差、安装包越做越大、部分版本带广告或后台联网行为 |
| 中文用户的两个高频痛点长期没人解决 | ① 外挂字幕大多是 GBK 编码，直接打开就是乱码；② 文件名里的中文序号排序错误（"第10集"排在"第2集"前面） |
| 轻量工具"看一眼就走"的需求被忽略 | 想快速截个图、逐帧看一段、变速看一集网课，往往要绕好几个菜单，甚至要装个专业剪辑软件 |
| 装机环境受限 | 办公电脑、机房、单位统一装的机器常常**没有管理员权限**，凡是需要提权的播放器都用不了 |

### 2.2 三个场景故事（PPT 第 2 页可直接用）

**场景 A · 客厅的影音机（普通家庭用户）**
客厅接电视的小主机上装了播放器，想干的事只有三件：双击片子、字幕自动出来、别乱码。
现实是：外挂的 GBK 字幕要手动改编码，蓝光格式的片源拖动进度条就黑屏，
HDR 电影整幅发灰像蒙了层雾。用户不知道问题出在哪，只能换片源。

**场景 B · 网课与自学（学生 / 职场自学用户）**
一边看网课一边截图做笔记，需要暂停、逐帧、加速听、把关键画面存下来。
现实是：截图要开截图软件、画质和画面尺寸都对不上；变速之后声音变成"花栗鼠"；
一节课两个小时，中间关掉再打开要重新找位置。

**场景 C · 字幕与素材整理（影视爱好者 / 内容创作者）**
下载的剧集是"第1集、第2集 …… 第10集"这样的中文文件名，一批一批看。
现实是：播放列表排序是乱的；字幕语言后缀 `.zh / .chs / .cht` 不被识别，
手动一集一集挂字幕；多音轨、多字幕轨的片子要反复进设置。

### 2.3 项目目标

> **做 Windows 上"默认播放器"应有的样子**：格式不挑、中文友好、随叫随到、用完就走。

三条价值主张：

1. **能放**：不因为格式把用户挡在门外，能放的都要放得好看（含 HDR 与硬件解码）。
2. **顺手**：符合中文用户习惯的排序、字幕、编码处理；界面全中文、全矢量图标、任意缩放都清晰。
3. **轻快**：启动、关闭、切文件都以毫秒计；不需要安装、不需要管理员、不联网上报。

## 3. 目标用户与画像

| # | 用户画像 | 典型行为 | 最在意的点 | 对应的功能 |
|---|---|---|---|---|
| 1 | **家庭影音用户**（客厅小主机 / 家用 PC） | 双击片子、全屏看、偶尔切音轨 | 字幕别乱码、HDR 颜色别发灰、遥控器/键鼠都能操作 | HDR 色调映射、字幕自动加载与编码识别、全屏自动隐藏控制栏、列表循环 |
| 2 | **学生与自学用户** | 网课、公开课、讲座录像 | 变速听不清不难受、截图方便、能记住看到哪 | 保持音高的变速、一键截图、断点续播、逐帧步进 |
| 3 | **影视爱好者 / 内容创作者** | 追剧、整理素材、看 HDR 片源 | 剧集顺序正确、多字幕轨、杜比视界信息透明 | 中文序号自然排序、语言后缀优先级、轨道页、媒体信息页 |
| 4 | **受限环境的装机用户**（办公 / 机房 / 单位） | 由 IT 统一发放、免安装、拷走即用 | 不要管理员权限、不要安装包、不要残留 | 免安装绿色目录、文件关联只写当前用户、取消关联可完全清理 |

## 4. 需求来源

| 来源 | 说明 |
|---|---|
| 团队自用观察 | 成员自己在看片、上网课、整理素材时反复遇到的麻烦（见 §2.2 三个场景） |
| 竞品实测 | 用同一批素材（含 GBK 外挂字幕、中文文件名剧集、蓝光格式片源、HDR 片子）逐项试用主流播放器，记录卡在哪一步（详见 `02-调研分析.md`） |
| 平台缺口 | Windows 桌面缺少一个"自带播放器本该做到"的选项：免安装、免提权、中文优先 |
| 工程约束反推 | 装机环境不允许提权、用户不愿等启动、素材来源复杂（下载站/网盘/录屏），这些约束直接决定了需求的优先级 |

**不做"想当然"的功能**：凡是无法从真实使用场景里说出"谁在什么时候需要它"的需求，一律不进清单；
凡是技术上一时做不完整的，宁可**明确提示用户**，也不做一个点了没反应的按钮（见 §9）。

## 5. 产品目标与成功指标

| 目标 | 指标 | 目标值 | 现状 |
|---|---|---|---|
| 开得快 | 自有代码启动耗时 | ≤ 20 ms | **6–8 ms**（调试构建实测，不含系统与显卡驱动创建窗口的时间） |
| 关得快 | 点击关闭到进程退出 | ≤ 100 ms | **约 46 ms**（发布构建、正在播放时）；空窗口约 15 ms |
| 能放 | 常见音视频格式覆盖 | 由解码内核决定，不自行缩水 | 视频/音频/网络串流全覆盖；镜像文件（ISO）等非媒体容器会明确告知 |
| 中文友好 | 外挂字幕编码识别 | ≥ 4 种 | **6 种**：UTF-8 / UTF-16（含 BOM）/ GBK / Big5 / Shift_JIS / Windows-1252 |
| 免打扰 | 是否要求管理员权限 | 否 | 文件关联只写当前用户区，**全程不需要提权** |
| 不崩 | 单个坏文件是否带走程序 | 否 | 每个工作环节独立隔离，坏文件只产生一条提示 |
| 可靠 | 自动化测试规模 | ≥ 150 项 | **200 余项**，含端到端真实解码播放测试 |
| 可分发 | 部署方式 | 免安装 | 绿色目录，拷贝即用，可直接打包分发 |

## 6. 典型用户旅程

### 6.1 第一次使用（30 秒内完成）

1. 拷贝目录到任意位置 → 双击主程序，直接可用（**无需安装、无需管理员**）。
2. 想让双击文件就用它打开 → 设置 → 系统集成 → "注册文件关联"（覆盖视频/音频/图片/播放列表 100 多种扩展名）。
3. 不想改了 → 随时"取消关联"，**不留任何残留**，也不会抢走其他播放器已经占用的关联。

### 6.2 日常使用

双击文件 → 自动播放（命令行/右键带来的文件视为明确的播放指令）→ 中途关闭 →
下次打开同一个文件自动回到上次位置 → 看到好画面按一下快捷键截图。

### 6.3 特殊素材

| 素材 | 期望行为 |
|---|---|
| HDR10 / HLG 影片 | 画面不发灰，高光柔和收敛；不需要的用户可以在设置里关掉色调映射 |
| 杜比视界影片 | 播放兼容基底层，并在信息面板写明杜比视界 Profile / Level / 单层或双层；无法正确还原的 Profile 明确提示 |
| 蓝光式 MPEG-TS（时间轴不从 0 开始） | 拖动进度条能正确落点，不黑屏、不冻结 |
| 同目录带外挂字幕 | 自动加载同名字幕，优先匹配 `.zh` / `.chs` / `.cht` 等语言后缀 |
| 几百 MB 的大图 / 3 万像素的照片 | 自动降到显卡可承受的尺寸，不因一张图耗尽显存 |
| 光盘镜像（ISO/UDF） | 明确提示"请先装载镜像"，而不是把镜像丢给解码器刷满错误 |

## 7. 功能需求

优先级：**P0 = 没有它产品不成立**；**P1 = 决定用户是否愿意长期用**；**P2 = 加分项**。

### 7.1 播放

| 编号 | 需求 | 说明 | 优先级 | 验收方式 |
|---|---|---|---|---|
| FR-01 | 播放本地音视频 | 常见容器与编码（由内置解码内核覆盖） | P0 | 端到端播放测试（真实解码 `testdata/` 素材） |
| FR-02 | 硬件解码 | 优先使用显卡解码，不可用时自动回退软件解码 | P0 | 真实素材探测（含可选的 HDR/杜比视界素材） |
| FR-03 | 播放控制 | 播放 / 暂停 / 停止 / 精确跳转 | P0 | 端到端测试 + 界面行为测试 |
| FR-04 | 单帧步进 | 暂停时"上一帧 / 下一帧"逐帧查看 | P1 | 界面行为测试（只移动播放头，不重建解码器） |
| FR-05 | 变速播放（保持音高） | 0.25x–4.0x，内置时域伸缩算法，不是简单变调 | P1 | 单元测试 + 人工试听 |
| FR-06 | 循环与随机 | A–B 循环、列表循环、单曲循环、随机 | P1 | 单元测试 |
| FR-07 | 音量与静音 | 0–200%，带软限幅，**不会爆音** | P0 | 单元测试 + 界面行为测试（音量确实到达声卡） |
| FR-08 | 音轨 / 字幕轨切换 | 多轨素材可选择；延迟微调 ±10 秒 | P1 | 引擎/界面测试 |
| FR-09 | 断点续播 | 记住每个文件上次播放位置 | P1 | 设置文档测试 |
| FR-10 | 截图 | 保存为 PNG 到"图片\MVP Snapshots" | P2 | 端到端测试（校验输出是合法 PNG） |
| FR-11 | 网络串流 | `http/https/rtsp/rtmp/udp/rtp/srt/HLS` | P1 | 手工验收 + 引擎单元测试 |
| FR-12 | 坏文件与异常不崩溃 | 损坏文件、无输出流等异常只产生提示 | P0 | 端到端测试（损坏文件不崩溃）+ "解码无输出"守护（12 秒内报错并停止空转） |
| FR-13 | 播放时阻止休眠 | 看片时屏幕/系统不休眠 | P2 | 平台层测试 |
| FR-14 | 拖入文件夹批量播放 | 递归扫描（最多 4 层）、自然排序、展开播放列表文件（`.m3u/.pls/.xspf`） | P1 | 单元测试 |

## 8. 非功能需求

| 编号 | 类别 | 需求 | 目标 / 现状 |
|---|---|---|---|
| NFR-01 | 性能 · 启动 | 窗口出现前只做最少的事（读命令行、写单实例标记、加载中文字体）；解码内核与声卡都按需初始化 | 自有代码 6–8 ms（调试构建）；发布构建体积约 14 MB（不含运行库） |
| NFR-02 | 性能 · 关闭 | 关闭时不清理积压数据、不等声卡超时、设置提前落盘 | 播放中约 46 ms，空窗口约 15 ms（发布构建） |
| NFR-03 | 性能 · 播放 | 视频/音频分别独立处理，慢的不会拖垮另一方（音频不中断） | 持续播放丢帧受监控；性能统计面板可见 |
| NFR-04 | 稳定性 | 单个坏文件不带走程序；长时间播放不因缓存无上限而耗尽内存 | 所有缓冲区都有上限（按数据量而非仅按数量）；异常只提示 |
| NFR-05 | 兼容性 | Windows 桌面；常见分辨率与高 DPI；窗口在小屏上可用 | 布局测试覆盖 320–2560 宽度 |
| NFR-06 | 易用性 | 零安装、零权限、零配置可用；设置项默认值即为推荐值 | 绿色目录分发 |
| NFR-07 | 隐私与安全 | 不联网上报、不采集用户数据、不弹广告；注册表只写当前用户 | 无任何遥测代码 |
| NFR-08 | 可维护性 | 四层结构：媒体引擎 / 系统集成 / 字幕解析 / 界面，依赖单向 | 各层可单独测试 |
| NFR-09 | 可测试性 | 自动化测试覆盖引擎、字幕、系统集成与界面行为 | 200 余项自动化测试 |
| NFR-10 | 许可合规 | 开源许可 GPL-3.0-or-later；内置解码内核为 GPL 构建 | 见 `02-调研分析.md` §10 风险与对策 |

## 9. 范围边界：明确不做的事（答辩加分项）

一个产品能不能说清"不做什么"，比"什么都做"更能说明设计水平。以下每条都是**有意为之**，
并且当用户真的遇到时，程序会**明确告知原因**，而不是静默失败或假装正常：

| 不做 | 原因 | 用户看到什么 |
|---|---|---|
| 图形字幕（PGS / VobSub）渲染 | 它们是位图字幕，需要文字识别才能转成可显示文本 | 明确提示该轨道无法显示 |
| 视频轨道切换 | 多视频流素材极少见，做半成品不如说清楚 | 轨道页写明"只解码第一条视频流" |
| 杜比视界增强层叠加 | 需要专用渲染路径；只播基底层时画面仍为 HDR10 效果 | 信息页写明 Profile / Level / 单层双层；Profile 5 明确提示无法正确还原 |
| 光盘镜像直接播放 | 镜像是容器里的容器，需要先"装载" | 提示先装载镜像，而不是刷一屏解码错误 |
| 主界面使用毛玻璃 / 半透明 / 亚克力 | 视觉上会与画面争夺注意力，且影响文字对比度 | 界面为纯色表面，文字对比度可稳定达标 |
| 联网上报与广告 | 与"免打扰、可信任"的产品定位冲突 | 无 |
| 支持非 Windows 平台 | 系统集成（文件关联、单实例、深色标题栏、防休眠）是产品价值的一半，跨平台"空实现"没有意义 | 明确标注仅 Windows |

## 10. 验收与验证方式

**用"能不能被反复验证"来判断需求有没有真正做完**，而不是靠演示一次成功。

| 验证层 | 规模 | 覆盖内容举例 |
|---|---|---|
| 端到端播放测试 | 16 项 | 真实解码素材，验证分辨率、时间戳单调、画面非空、跳转落点、暂停时时钟冻结、内嵌字幕解码、截图是合法 PNG、**损坏文件不崩溃** |
| 界面行为测试 | 11 项 | 按真实调用顺序驱动播放流程：打开前就关字幕/音轨、时钟与真实时间的一致性、持续播放的丢帧数、跳转后时钟仍一致、音量与静音真的到达声卡、关闭时不等积压 |
| 引擎单元测试 | 59 项 | 时钟、帧队列、缓冲池、变速算法、增益软限幅、播放列表、轨道选择、EXIF 方向… |
| 字幕解析测试 | 53 项 | 含 GBK 中文、ASS 格式行重排、WebVTT 设置 |
| Windows 集成测试 | 31 项 | 文件关联注册/注销、单实例、外壳与显示器适配 |
| 界面与命令行测试 | 46 项 | 画面历史环、快捷键表、滚轮步进、"命令行带来的文件一定自动播放"、"参数不会变成偏好设置" |
| 真实注册表测试 | 5 项（默认跳过） | 注册 → 检查 → 注销 → 确认**零残留**；并确认**不抢占其他播放器已有的关联**（在开发机上同时装有其他播放器的真实环境中通过） |
| 大素材可选项 | 按需 | HDR / 杜比视界真实样本需另行提供（体积过大不入库），带看门狗避免挂死；单个文件的排查工具可打印"打开 → 解码 → 跳转 → 停止"每步耗时 |

**验收原则**：
- 素材缺失或设备不可用的测试会打印"跳过"并**通过** —— 因此绿色结果不等于素材存在，验收前需确认素材齐备。
- 性能类结论一律以发布构建为准。
- 演示中出现的每个结论，都能在测试或实测数据里找到出处。

## 12. 附录：给非技术读者的术语表

| 术语 | 通俗解释 |
|---|---|
| 容器 / 格式（MP4、MKV、TS…） | 装视频、音频、字幕的"箱子"。箱子不同，能装的编码也不同 |
| 编码（H.264、H.265、AV1…） | 箱子里的"压缩方式"。同一部片子可以用不同方式压缩 |
| 硬件解码 | 让显卡负责解开压缩，CPU 更省电、更流畅；显卡不支持时自动改由 CPU 来做 |
| 解复用 | 把"箱子"拆开，把视频流、音频流、字幕流分别交给对应处理环节 |
| 跳转落点 | 拖动进度条后画面真正的开始位置。有些格式只能跳到最近的"关键帧" |
| 色调映射 | HDR 电影本来按更亮更鲜艳的标准制作，在普通屏幕上直接显示会发灰；色调映射是把它"翻译"成普通屏幕能好看地显示的样子 |
| 杜比视界基底层 | 杜比视界影片里，有一层是普通 HDR 播放器也能正常放的"兼容层"。只播这一层时，画面是 HDR10 效果，但不会更亮更艳 |
| 关键帧 | 画面序列里可以独立还原的整帧，跳转必须落在它上面 |
| 缓存 / 队列 | 预先解出来的画面排的队。队列有上限，否则 4K 素材会瞬间吃掉半个内存 |
| 免安装绿色版 | 拷到任何位置双击就能用，不改系统、不留安装记录 |
| 文件关联 | 告诉 Windows"这种后缀的文件默认用谁打开" |
