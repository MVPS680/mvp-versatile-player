# MVP-Versatile-Player

**多功能音视频与图片播放器** — 使用 Rust 编写，直接集成 FFmpeg 内核，面向 Windows 桌面。

对标 VLC / PotPlayer 的使用习惯：原生资源管理器「打开方式」与右键菜单、可一键注册的文件关联、
完整的播放列表与字幕支持、图片查看器，以及为启动速度优化的实现。

```
┌──────────────────────────────────────────────────────────┐
│ 文件  播放  视频  音频  字幕  工具  帮助                     │  菜单栏
├───────────────────────────────────┬──────────────────────┤
│                                   │                      │

│                                   │  播放列表 / 轨道 /   │
│                                   │  章节 / 信息         │
├───────────────────────────────────┴──────────────────────┤
│ 00:12:04  ─────────●───────────  02:31:55   ⏮ ⏯ ⏭  🔊 ▣  │  控制栏
└──────────────────────────────────────────────────────────┘
```

## 功能

### 播放

- **直接链接 FFmpeg**，不启动 `ffmpeg.exe` 子进程，没有管道预热延迟。
- **硬件解码**（D3D11VA，回退 DXVA2），不可用时自动回到软件解码。
- **HDR10 / 杜比视界**：识别 BT.2020 + PQ/HLG，读出容器里的杜比视界配置记录
  （Profile / Level / 单层或双层 / 兼容层），并逐帧读取 RPU（FFmpeg 7.1 起由 HEVC
  解码器直接附在帧上）。基底层按 PQ 还是 HLG 处理，由文件自己的兼容层决定 ——
  Profile 8.4 是 HLG 文件，按 PQ 曲线映射会整幅发灰，这一点已经修正；色调曲线按每帧
  的亮度范围（RPU Level 1）瞄准场景。信息面板给出「动态范围」与「杜比视界」两行，
  不能做的部分会明确写出来。设置 → 视频 → 「HDR 色调映射」关闭后不做任何映射，
  原片信号直通。
- **打不开的东西会明确说出来**：光盘镜像（ISO/UDF）不是媒体容器，会提示先「装载」，
  而不是把镜像丢给解复用器刷满解码错误；解复用器持续投喂而解码器长时间没有输出时，
  12 秒内报出「解码无输出」并停下，不会空转。
- **时间轴不从 0 开始的容器也能正确跳转**：蓝光式 MPEG-TS 的 `start_time` 常在 4200 秒，
  跳转要把播放时间换算成容器时间；而这类容器没有索引，跳转靠二分查找读包，
  会回调播放器自身——这条路径上的自死锁（画面会永久冻结）已修复。
- 视频、音频、网络串流（`http` / `https` / `rtsp` / `rtmp` / `udp` / `rtp` / `srt` / HLS）。
- 播放 / 暂停 / 停止、精确跳转、单帧步进（`上一帧` 与 `下一帧`，暂停时逐帧查看）。
- **双击媒体文件即开始播放**：命令行/「打开方式」带来的文件是明确的播放指令；
  想让某一次启动停在第一帧，用 `--no-autoplay`（只影响那一次启动）。
- **保持音高的变速播放**（0.25x – 4.0x）：内置 SOLA 时域伸缩算法，不是简单的重采样。
- A–B 循环、列表循环、单曲循环、随机播放。
- 音量 0–200%（带软限幅，不会爆音）、静音。
- 音轨 / 字幕轨切换，音频延迟与字幕延迟微调（±10 秒）。
- 断点续播：记住每个文件上次的播放位置。
- 截图保存为 PNG（`Pictures\MVP Snapshots`）。

### 画面调节与画质增强

- **画面调节**（`视频 → 画面调节…`，`Ctrl+P`）：亮度、对比度、饱和度、色温、色调、锐度、
  Gamma 共七项，每项都有滑块与数值读数，拖动即时预览。
- 全部处理都在 **GPU 着色器**里完成：一次采样、一个 pass，不重传纹理、不复制画面，
  也不碰源文件。驱动拒绝编译着色器时自动退回原来的绘制路径，画面照常显示。
- **只对视频生效**：图片与音频不受影响，照片永远保持作者给的颜色。
- **一键重置**：所有滑块回到默认值。默认值就是「不干预」，此时渲染完全走原来的路径 ——
  「没调过」不是「调了但幅度很小」，而是同一个绘制调用。
- **画质增强**：总开关 + 强度，外加自动色阶、自动色彩、降噪、去块、锐化。它按每帧自己的
  直方图做轻微校正（暗部抬升、色彩补足、边缘平滑），**默认关闭**。统计量取自每帧最长边
  不超过 160 像素的抽样副本，每秒最多 10 次，目标值再逐帧平滑推进，所以统计量的抖动不会
  让画面呼吸，也不保留帧历史 —— 不会有拖影。**关闭后着色器立即退出渲染路径，不留残影。**
- **参数记忆**：全局共用一组，或按文件各记一组（最多 200 个，超出时替换最久未用的那个）；
  用的是与断点续播相同的文件键。
- **截图**：默认保存解码出的原始帧；设置 → 截图 里的「截图包含画面调节」打开后，
  会按当前调节重新渲染一帧再保存（仍不含字幕与界面）。

### 音效增强

- **入口**：菜单栏 `音频 → 音效增强…`，或底栏 `轨道` 菜单里的 `音效增强…`；默认**关闭**。它是一个浮层面板而不是设置页：不压暗界面、
  不抢键盘，播放中随时可调（面板位置与设置窗口同层）。
- **十段均衡器**：31 Hz – 16 kHz 八度分段，每段 ±12 dB；预设 平直 / 温暖 / 明亮 / 人声 /
  摇滚 / 低音增强 / 高音增强 / 流行 / 自定义。曲线用**与滤波器同一套系数**绘制
  （`Coeffs::magnitude`），并且按输出设备自己的采样率画 —— 16 kHz 在 22 kHz 的设备上不存在，
  界面不会假装它存在。
- **低音与清晰度**：120 Hz 低架 + 二次谐波（小扬声器也能听出低频）、6 kHz 高架 + 瞬态增强。
- **响度归一化**：K 加权（BS.1770 的那两级双二阶）短时电平，向目标缓慢逼近，目标可关闭。
- **保护**：1 ms 前视峰值限制器 + −3 dBFS 软膝（`tanh`），**排在链尾**，其后不再有任何一级
  能加增益；增益降低取自**所有声道的最大值**并统一施加，避免大声段人声跑偏。
- **空间感**：中侧立体声宽度，加一段 8 梳状 + 4 全通的 Schroeder 残响（左右声道延迟错开，
  单声道音源也能得到有宽度的尾音）。残响是**叠加**在干声上的湿信号，所以不产生延迟；
  残响量为 0 时这一级完全不介入。只影响输出的前两个声道。
- **处理位置**：全部在 **cpal 设备回调线程**内完成，参数通过无锁 seqlock（原子块 + 世代号）
  发布，回调线程不分配、不加锁、不做 IO；参数按**时间**平滑（约 30 ms）而不是插值系数，
  因此拖动滑块时没有台阶噪声。
- **关就是真的关**：总开关关闭 → 音效链根本不进入回调；开关打开但所有控件都在中性值 →
  自动旁路（`Snapshot::is_idle`），**逐样本与未启用时完全一致**（单元测试断言逐比特相等）。
- **延迟**：只有限制器的前视约 1 ms；空间残响是湿声叠加，不额外增加延迟。界面显示实际延迟。
- **持久化**：`audio_enhance` 写进 `settings.json`，旧配置文件缺这一段会落到中性默认值。

### 字幕

- 内嵌字幕（SRT / ASS / SSA / MOV_TEXT / WebVTT）与外部字幕文件。
  打开文件时按设置决定用哪一个：默认「外部字幕优先」，同目录有同名字幕就用它；
  关掉这个开关则优先用文件自带的内嵌字幕，没有内嵌字幕时才回退到外部文件。
- **图形字幕（PGS / VobSub / DVB）**：内嵌轨道与外部文件（`.sup`、VobSub 的
  `.idx` + `.sub`）都直接按位图绘制在画面上，不需要 OCR，颜色和排版与片源一致。
- 自动加载同目录下的同名字幕，优先匹配 `.zh` / `.chs` / `.cht` 等语言后缀。
- 自动识别编码：UTF-8 / UTF-16 BOM / **GBK** / Big5 / Shift_JIS / Windows-1252。
  中文外挂字幕大量使用 GBK，这一点很重要。
- 字号、颜色、衬底、距底部距离均可调整。

### 图片

- PNG / JPEG / GIF / WebP / BMP / TIFF / ICO / TGA / AVIF / JXL / QOI / PNM / EXR 等。
- **动画 GIF / WebP / APNG** 逐帧播放。
- 缩放、平移、旋转、水平/垂直翻转、适应窗口、100% 原图。
- 幻灯片播放。
- **按 EXIF 方向自动旋转**，手机照片不会侧躺。
- 超大图片自动缩小到显卡纹理上限，不会因一张 30000 像素的图而耗尽显存。

### 与 Windows 集成

- **原生「打开方式」**：注册后在资源管理器中右键即可选择 MVP。
- **一键文件关联**：设置 → 系统集成 → 「注册文件关联」，覆盖视频、音频、图片、播放列表
  共 100 多种扩展名；**只写入当前用户注册表（HKCU），不需要管理员权限**。
- 可选的右键菜单项「用 MVP-Versatile-Player 打开」。
- **单实例**：已在运行时，再次双击文件会把文件加入现有窗口的播放列表并前置窗口，
  而不是开出第二个窗口（基于命名互斥体 + `WM_COPYDATA`）。
- 深色标题栏、跟随主题；
- 播放时阻止屏幕/系统休眠。

### 界面

- **可切换的配色（设置 → 常规 → 外观 → 主题配色）**，共五种，选中即生效并写入
  `settings.json`：
  - **陶土灰（默认）**：暖调灰阶表面（背景 → 面板 → 卡片 → 内凹）+ 灰调陶土强调色；
  - **灰绿 / 雾蓝 / 藕紫**：同一套灰阶体系的另外三种灰调强调色，其中雾蓝是唯一的冷色；
  - **原版蓝**：改版前的蓝色主题，数值按原样保留。
- 莫兰迪四色压着**彩度上限**（表面/文字 ≤25%、强调色 ≤42%、语义色 ≤45%），
  写在 `theme.rs` 的 `no_colour_in_the_palette_shouts` 测试里，原版蓝是唯一例外；
  换配色只换色相、不换层级——半透明填充的 alpha 由 `Recipe` 统一给出，
  `every_palette_draws_its_fills_at_the_same_strength` 守着这一点，
  对比度下限则由 `every_palette_has_enough_contrast` 对每种配色逐一测量。
  画面才是主角，界面不与之竞争。
- 全部图标为**矢量绘制**（24×24 网格），在任意 DPI 下都清晰，不使用 emoji。
- **视频、音频、图片三套各自独立的界面**，而不是同一套布局换个内容：
  - **视频**：章节刻度与悬停时间预览的时间轴、底栏直接快切音轨/字幕、
    A–B 循环（时间轴上画出区间）、画面比例/旋转/镜像快捷菜单；
    侧边栏为播放列表、轨道、章节、媒体信息。
  - **音频**：唱片海报 + 进度环，右侧为播放队列、歌词（字幕轨当歌词滚动显示）、
    音频参数与信息；底栏是大音量滑杆、变速与输出设备选择。
  - **图片**：底部缩略图胶片条，底栏工具条含缩放、适应/填充/100%、旋转、翻转、
    背景（深色/纯黑/浅色/棋盘格）与幻灯片（间隔、随机顺序）；侧边栏为图片信息（EXIF）。
- 后置的性能统计面板（解码帧数、丢帧、队列深度、音频欠载、启动耗时）。
- 全屏时控制栏自动隐藏，鼠标移动即唤回。

## 快速开始

### 依赖

| 组件 | 版本 | 说明 |
|---|---|---|
| Rust | 1.85+ | `x86_64-pc-windows-msvc` |
| MSVC 生成工具 | VS 2022 | 需要 `link.exe` 与 Windows SDK |
| FFmpeg 开发包 | 9.0（共享库） | 见下 |
| libclang | 任意 15+ | `ffmpeg-sys-next` 生成绑定需要 |

### 准备 FFmpeg 开发包

```powershell
.\scripts\setup-ffmpeg.ps1
```

脚本会找到（或下载）BtbN 的 FFmpeg 9.0 **共享库**构建，探测 `libclang`，
并把两个路径写进 `.cargo/config.toml`。

> `.cargo/config.toml` 是**本机生成**的文件，已被 `.gitignore` 忽略。
> 它记录的是「这台机器上 SDK 装在哪」——这是机器的事实，不是项目的配置：
> 入库会让每次 `git pull` 都用别人的绝对路径盖掉自己的。所以每台机器跑一次
> 本脚本即可，之后永远不需要手改路径。
>
> 脚本可以重复运行：已解压的 FFmpeg 会被复用（不会重新下载 1 GB），
> 没变化时不会重写配置。常用参数：`-FfmpegDir <已有开发包>`、
> `-LibclangPath <目录或 dll>`、`-NoDownload`（不联网，找不到就报错）。

`scripts/dev.ps1` 在发现配置缺失时会自动跑一次这个脚本（带 `-NoDownload`，
避免一次测试命令静默下载一整个 GB），所以新克隆的仓库直接：

```powershell
.\scripts\dev.ps1 test --workspace
```

也能跑起来。

<details>
<summary>手动准备</summary>

需要一个**共享库（shared）**构建，且需包含 `include/`、`lib/*.lib` 与 `bin/*.dll`：

<https://github.com/BtbN/FFmpeg-Builds/releases> →
`ffmpeg-n9.0-latest-win64-gpl-shared-9.0.zip`

> ⚠️ 请使用 **n9.0 发行分支**，不要用 `master`。`master` 的枚举里包含
> `ffmpeg-next 9.0.0` 尚不认识的编解码器，会编译失败。

解压后重跑 `scripts/setup-ffmpeg.ps1 -FfmpegDir <解压目录>` 即可；
也可以自己写 `.cargo/config.toml`（或直接设置同名环境变量）。两者都只是
本机路径的记录，不入库：

```toml
[env]
FFMPEG_DIR = { value = "C:/ffmpeg-dev/ffmpeg-n9.0-latest-win64-gpl-shared-9.0", force = false }
LIBCLANG_PATH = { value = "C:/path/to/clang/native", force = false }
```

`LIBCLANG_PATH` 缺失时，脚本会按下面顺序找（见 `scripts/ffmpeg-env.ps1`）：
环境变量 → 已写的配置 → `python -c "import clang"`（`pip install libclang` 自带的
`libclang.dll` 就在 `Lib/site-packages/clang/native`）→ LLVM / Scoop /
Visual Studio 自带的 LLVM。如果把 LLVM 装到 `C:\Program Files\LLVM`
（`clang-sys` 会自己去那里找），就完全不需要写 `LIBCLANG_PATH`。

</details>

<details>
<summary>构建失败时先看这两条</summary>

- `Unable to find libclang: … set the LIBCLANG_PATH environment variable …`
  —— `ffmpeg-sys-next` 的 bindgen 步骤没找到 DLL。重跑
  `scripts/setup-ffmpeg.ps1`；它找不到时会打印该装什么。
- `FFMPEG_DIR` 相关的链接错误 / 找不到 `avcodec.lib`
  —— 开发包不在预期位置。用 `scripts/setup-ffmpeg.ps1 -FfmpegDir <目录>` 指过去。

两者都只影响本机构建输入，不会影响仓库里的任何文件。

</details>

### 构建

```powershell
# 开发构建（带控制台输出与日志）
.\scripts\dev.ps1 build -p mvp-player

# 运行
.\scripts\dev.ps1 run -p mvp-player

# 发布构建（LTO、strip、无控制台窗口）
.\scripts\dev.ps1 build --release -p mvp-player

# 测试
.\scripts\dev.ps1 test --workspace
```

`scripts/dev.ps1` 把 FFmpeg 的 `bin` 目录加入 `PATH` 后转发给 cargo
（缺配置时先跑一次 `setup-ffmpeg.ps1`）；它存在的唯一原因是
`cargo run` / `cargo test` 需要能在运行时找到那些 DLL。
`build.rs` 会把 DLL 复制到 `target/<profile>/`，所以直接运行
`target\release\mvp-versatile-player.exe` 也是可以的。

### 打包分发

```powershell
.\scripts\package.ps1
```

产物在 `dist\MVP-Versatile-Player\`，包含可执行文件、全部 FFmpeg DLL、
图标与说明文件。整个目录可以直接拷贝到别的机器运行，无需安装。

## 命令行

```
mvp-versatile-player [选项] [文件或文件夹...]

  -f, --fullscreen       以全屏启动
      --no-autoplay      本次启动打开文件后暂停（只影响这一次启动）
      --no-audio         不打开音频输出
      --volume <值>      初始音量（0.0-2.0 或 0-200）
      --speed <值>       初始速度（0.25-4.0）
  -s, --subtitle <文件>  为第一个文件加载字幕
  -h, --help             帮助
  -v, --version          版本与 FFmpeg 版本
```

文件夹参数会被递归扫描（最多 4 层），并按自然顺序排序——`第2集` 会排在 `第10集` 前面。
播放列表文件（`.m3u` / `.pls` / `.xspf`）会被展开为其中的条目。

### mvp-core 的播放管线

```
  ┌──────────┐  压缩包   ┌───────────────┐   帧    ┌────────────┐
  │  解复用  ├──────────►│  视频解码器   ├────────►│  帧队列    │──► 界面
  │  线程    │           └───────────────┘         └────────────┘
  │          │  压缩包   ┌───────────────┐  f32    ┌────────────┐
  │          ├──────────►│  音频解码器   ├────────►│ cpal 声卡  │
  │          │           └───────────────┘         └────────────┘
  │          │  压缩包   ┌───────────────┐
  │          ├──────────►│  字幕解码器   │──► 字幕队列
  └──────────┘           └───────────────┘
```

几个关键决定：

- **音视频分别解码**。解复用器把包分发给各自的解码线程，因此慢速视频解码永远不会
  让声卡断粮。
- **控制指令不排队**。跳转与切换音轨通过共享状态下发，不走包队列——否则一条
  「全部丢弃」的指令会排在几十个包后面，而解码线程还在对着已经过时的时钟慢慢吞。
  视频包在队列满时**直接丢弃**（画面可以牺牲），音频包则保持背压（声音不能断）。
- **所有队列都按字节数设上限**，不只是按帧数。4K RGBA 一帧就是 33 MB，
  「缓存 16 帧」这种写法会瞬间吃掉半个 GB。
- **主时钟是系统时钟**。这一点反直觉：声卡看起来是天然的时间源，但驱动报告的只是
  *写入* 的采样数——有的驱动一次吞掉一整秒音频，有的在停止回调后继续播放已缓冲的
  数据。用设备计数器当时钟，画面会以数倍速度狂奔或直接冻住。系统时钟是单调且精确的，
  代价是两个晶振之间的漂移（真实硬件上几十 ppm，一部电影累计几百毫秒），
  远比一个「根本不准」的时钟划算。
- **色彩矩阵按元数据选择**。HD（BT.709）素材不会按 SD（BT.601）转换，
  否则饱和度会肉眼可见地偏掉。
- **像素只拷贝一次**。swscale 直接写进池化缓冲区，界面再把这块内存
  零拷贝地重新解释成 `Vec<Color32>` 交给 GPU。
- **每个工作线程都捕获 panic**。损坏的文件只会变成一条错误提示，不会带走整个播放器。

### 杜比视界（Dolby Vision）

杜比视界文件带两套记录：容器里的**配置记录**（Profile / Level / 层 / 兼容层）和每帧
的 **RPU**（参考处理单元；FFmpeg 7.1 起 HEVC 解码器把它解析出来，以
`AV_FRAME_DATA_DOVI_METADATA` 附在帧上）。`mvp-core/src/dolby.rs` 把两者都读出来，
并且是**唯一**决定「这个文件按什么处理」的地方：渲染线程、信息面板、打开文件时的提示
问的是同一个 `DvPlan::resolve`，所以三者不会给出三种说法。

用到的是：

- **基底层传输函数**：由配置记录的兼容层 ID 决定（1/6 → PQ，4 → HLG，2/0 看流自身的
  标签），RPU 的 `signal_eotf` 优先。这不是外观问题：把 HLG 兼容基底层按 PQ 曲线映射，
  画面会明显发灰。
- **逐帧亮度范围**：RPU Level 1 的 min/avg/max 换算成尼特，色调曲线按这个范围求解并做
  时间平滑；帧里没有 Level 1 时退回色彩元数据给出的母版窗口。
- **重塑曲线**（`mvp-core/src/dolby/reshape.rs`）：按 RPU 描述的分段多项式 / MMR 曲线
  还原基底层，并实现增强层残差需要的非线性反量化（NLQ）。**默认关闭**，见下。
- **报告**：Profile / Level / 单层或双层 / 兼容层、信号色彩空间（YCbCr 还是 IPT）、
  信号位深、母版亮度窗口、活动画面区域（Level 5）、目标显示器微调块数量（Level 2），
  以及 RPU 是否带非线性重塑（多项式 / MMR / NLQ）。

### 重塑为什么默认关闭

这一段是本仓库「不发布无法验证的色彩数学」这条规矩的直接后果，也是下一步的入口。

`dolby/reshape.rs` 的曲线形状与系数缩放取自 libplacebo（mpv 的杜比视界实现），并用它的
公开结构文档核对单位；本机链接的 FFmpeg 带 `libplacebo` 滤镜，所以同一帧可以让两边各渲染
一次、逐字节对比（`tmp/dv-compare.ps1` + `examples/dv_reshape_dump.rs`）。实测（手上唯一的
杜比视界样本，手机拍摄的 Profile 8.4：6 段多项式亮度 + MMR 色度）：

| 对比 | 结果 |
| --- | --- |
| 只应用**亮度**曲线，与不做重塑对照 | 28.5 dB PSNR（效果量级与 libplacebo 的 29.4 dB 一致，均值变化同阶）→ **亮度曲线通过** |
| 再加上**色度**曲线 | 均值被推得远超 libplacebo 的变化 → **色度曲线尚未对齐**（MMR 的输入域 / 位置 / 截断处仍有差异） |

所以设置 → 视频 → 「杜比视界重塑」默认**关闭**：关闭时不进入该处理（零开销），开启后
画面可能与杜比视界设备不同。等色度那一段对照通过之后再改默认值。

### 增强层（Profile 7 双层）现状

RPU 里增强层需要的数学（NLQ 残差补偿、折叠系数、与重塑的应用顺序）已经实现并有单元测试，
但**没有帧喂给它**：解复用器只开一条视频流，而且**本机上没有任何带增强层的杜比视界文件**
（所有样本的 `el_present` 都是 false）。因此「解码增强层（双轨 / 单轨内嵌）并把残差合成
进去」这条路可以写，但写完无法验证 —— 需要一个 P7 双层样本才能接通并对照。

刻意不做，每条都有理由写在模块文档里：

- **不合成增强层**。Profile 7 的额外高光细节在第二条视频流（双轨）或同一码流的额外 NAL
  （单轨双层）里，要靠 RPU 的 NLQ + MMR 合成；解复用器只开一条视频流，播放器会说出来
  而不是假装。MEL 几乎没有残差，所以 Profile 7 当作 HDR10 基底层看是站得住的。
- **不转换 Profile 5**。它的基底层是 IPT（ICtCp），只有杜比视界的反演能还原；RPU 自带
  的矩阵读出来了，但变换没有跑，理由同上 —— 播放器会提示颜色可能不正确。
- **不向显示器传递元数据**。把 RPU 交给杜比视界显示器需要操作系统、驱动与终端三方都
  同意承载这条比特流；Windows 上这件事属于 DXGI 高级颜色与系统媒体栈，OpenGL 窗口没有
  参与的途径。「关闭色调映射」保证的是基底层信号未被改动，而不是杜比视界元数据到达屏幕。

看一个文件到底带什么：

```powershell
cargo run -p mvp-core --example dv_probe -- "C:\path\to\dolby.mkv" 8
```

开发时用它的输出与 `ffprobe -show_frames` 的输出逐字段对照过（手上那个手机拍摄的
Profile 8.4 样本：HLG 兼容、10 → 12 位、亮度是 6 段多项式、色度是 MMR、母版 0–1001
尼特）。

### 启动速度

窗口出现前只做三件事：解析命令行、写一次单实例互斥体、读一个中文字体。
FFmpeg 的表在第一次用到时才初始化，声卡在第一次播放时才打开。

实测（本机，调试构建）：自有代码耗时 **6–8 ms**，窗口与 OpenGL 上下文创建
由 `eframe`/`winit`/显卡驱动决定（本机约 200 ms）。发布构建配合 `lto = "fat"`、
`codegen-units = 1`、`strip = "symbols"`，可执行文件约 14 MB
（不含 FFmpeg 的 180 MB DLL）。

每次运行都会写日志到 `%APPDATA%\MVP-Versatile-Player\mvp.log`（超过 2 MB 自动轮转，
保留一份历史）。发布版本没有控制台，这是排查问题的唯一途径，
菜单「帮助 → 查看运行日志」可以直接打开它。

### 关闭速度

关闭同样是「一键就走」：**实测（发布构建，播放中关闭窗口）从点击关闭到进程退出
约 46 ms，空窗口约 15 ms**。三处关键设计：

- **不清理积压**。解复用的 `abort` 标志在每个工作线程循环的最前面检查，通道里
  剩下的几十个数据包直接丢弃；只按 `Stop` 消息退出的话，那些包会被解码、转换、
  再扔掉——实测视频线程 167 ms、音频线程 70 ms 全花在这上面。
- **声卡不会拖住线程**。音频解码器写队列时最多阻塞 500 ms 做背压，而**暂停**时
  输出回调不再运行，队列永远不会被消费；停止时先把声卡标记为关闭，这次等待立刻
  结束（否则暂停后关窗要等 500 ms）。
- **写设置很便宜**。会话每 2 秒已经落盘一次，退出时只是把最后一个文档写出去
  （约 1 ms），IPC 线程通过一条消息退出（约 2 ms）。

只有引擎释放超过 5 ms 时才写日志（`释放播放引擎耗时 …`），平时保持安静。

## 已知限制

- **仅支持 Windows**。`mvp-platform` 的其他平台分支可以编译，但功能是空实现。
- **图形字幕的坐标基于源字幕画布**：PGS 的坐标就是视频像素，位置精确；VobSub 使用
  自己的 DVD 画布（如 720×480），在分辨率差异较大的片源上会有轻微缩放偏差。
- **HDR 色调映射是 CPU 上的近似实现**：按亮度曲线 + BT.2020→BT.709 矩阵逐像素换算，
  逐帧动态元数据里只用到 RPU Level 1 的亮度范围（用来瞄准曲线），RPU 的目标显示器微调
  （Level 2）与非线性重塑没有参与，极饱和的高光会有偏差；实测调试构建 1080p 约 22 ms/帧、
  4K 约 90 ms/帧（发布会快数倍），真正的解法是着色器实现。
- **HDR/SDR 映射不在画质增强里**：它由上面这条 CPU 色调映射承担，画质增强只处理已经
  映射好的 SDR 画面。把色调映射搬进画面调节用的那个着色器是下一步的工作。
- **画面调节只作用于显示层**：截图默认仍是解码出的原始帧（可在设置 → 截图 里改成包含
  画面调节），源文件从不被修改，音轨、字幕轨与播放时钟也完全不经过它。
- **画质增强是单通道的近似**：降噪与去块共用同一次边缘感知平滑（一次 pass 分不清块边界
  与真实边缘），也没有时域降噪 —— 换来的是不拖影、不闪烁，代价是对时域噪声无能为力。
- **杜比视界只播基底层，增强层未接通**：Profile 7/8 显示的是 HDR10/HLG 兼容基底层
  （传输函数按兼容层 ID 选，不再是「一律 PQ」），RPU Level 1 的亮度范围用来瞄准色调曲线；
  增强层（FEL/MEL）的解码与残差合成**没有实现**（本机也没有 P7 样本可验证），
  重塑曲线已按 libplacebo 实现但**默认关闭**（亮度曲线已对照通过、色度曲线尚未），
  Profile 5 的 IPT 基底层无法正确还原 —— 这些都会在信息面板与打开提示里说出来，
  而不是假装正常。元数据也无法到达显示器（见「架构 → 杜比视界」）。
- 硬件解码取回画面时经过一次显存→内存拷贝：省下的是码流解码，
  而不是这次带宽。真正零拷贝的路径需要把 D3D11 纹理直接交给渲染器，
  那是下一步的工作。
- 播放列表的拖拽排序通过行内箭头实现，没有实现鼠标拖放。
- **不能切换视频轨道**。文件里有多条视频流时只解码第一条，轨道页会明确写出来，
  而不是给出一个点了没反应的列表。
- **不记忆窗口尺寸与位置**。启动时会读取 `window_size` / `window_pos` / `maximized`，
  但退出时不会回写，所以每次启动都是默认尺寸。
- **视频流的旋转元数据不生效**（手机竖拍的视频可能侧躺），信息页会显示该元数据。
- 单帧后退用的是界面自己保存的画面历史（默认 12 帧 / 128 MB，可在性能统计里看到
  当前深度），因此刚打开文件、还没显示过任何画面时「上一帧」是灰的。
- `.m3u8` 既可能是用户播放列表也可能是 HLS 清单，播放器会嗅探内容来区分。
- 变速播放的 SOLA 算法在 0.5x 以下与 3x 以上会有轻微调制感，
  这是时域伸缩的固有代价。
