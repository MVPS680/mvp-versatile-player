# AGENTS.md

MVP-Versatile-Player — a Windows-only audio/video/image player. Rust workspace,
FFmpeg linked **in-process** (never spawns `ffmpeg.exe`), egui/eframe UI.

Feature list, setup and limitations live in [README.md](README.md) (Chinese) —
read it, don't duplicate it here.

## Commands

FFmpeg is linked dynamically, so anything that *runs* a binary needs its `bin`
on `PATH`. Use the wrapper instead of bare `cargo`:

| Task | Command |
|---|---|
| Build (dev) | `.\scripts\dev.ps1 build -p mvp-player` |
| Run | `.\scripts\dev.ps1 run -p mvp-player` |
| Test everything | `.\scripts\dev.ps1 test --workspace` |
| Test one crate | `.\scripts\dev.ps1 test -p mvp-core` |
| Clippy | `.\scripts\dev.ps1 clippy --workspace --all-targets` |
| Registry tests (writes HKCU) | `.\scripts\dev.ps1 test -p mvp-platform --test registry_live -- --ignored --test-threads=1` |
| Package | `.\scripts\package.ps1` → `dist\MVP-Versatile-Player\` |
| Probe one file/URL | `cargo run -p mvp-core --example seek_probe -- <file-or-url> [seconds]` |

`crates/mvp-core/examples/seek_probe.rs` is the smallest working example of
driving the engine (open → poll events → take frames → seek → stop); start there
rather than reading `app.rs`.

Custom repo scripts (not cargo): `scripts\setup-ffmpeg.ps1`,
`scripts\make-testdata.ps1`, `scripts\make-icon.ps1`, `scripts\ffmpeg-env.ps1`
(the single source of truth for where the FFmpeg kit is — do not hard-code
`C:\ffmpeg-dev\...` elsewhere).

### Toolchain traps

- `.cargo/config.toml` is **generated per machine and gitignored**; `dev.ps1`
  runs `setup-ffmpeg.ps1 -NoDownload` when it is missing. Never commit it.
- `ffmpeg-sys-next` **always** runs bindgen, so libclang is mandatory on every
  machine. A missing/empty `LIBCLANG_PATH` is a *set* variable and will defeat
  clang-sys's own search — never write an empty value.
- Do **not** run `cargo fmt --all`. The repo is hand-formatted at ~100 columns;
  only new files need to be individually `rustfmt --check` clean.
- Clippy is **not** warning-free on master (pre-existing: float-precision lints in
  `mvp-core/src/hdr.rs`, const assertions in `mvp-player/src/theme.rs`). Check
  whether a warning is yours before "fixing" it.
- Prefer **release** builds when judging anything time-related; `profile.dev`
  uses `opt-level = 1` and the CPU tone map costs ~22 ms/frame at 1080p in dev.
- PowerShell surfaces git's stderr progress as `NativeCommandError` with exit
  code 1 even on success — read the output line, not the exit code. Commits go
  through `git commit -F` (backticks get mangled in double-quoted strings).
  Remote is gitee only, branch `master`.

### Tests

- Missing fixtures and unavailable audio devices cause tests to print
  `skipping: …` and **pass**. A green run does not prove the fixtures exist.
- `scripts/make-testdata.ps1` is **not** the complete source of `testdata/`:
  `scene.mp4` is never generated by it, and its `with_subs.mp4` recipe produces
  no subtitle stream at all while the committed fixture has one. Re-running the
  script damages fixtures that `crates/mvp-core/tests/playback.rs` and
  `player_loop.rs` assert on.
- Two timing tests are known-flaky on master, independent of your change —
  re-measure before blaming a diff:
  `player_loop.rs::stopping_releases_the_workers_promptly` (300 ms bound on
  `Engine::stop`; the demuxer join is what overruns) and
  `seek_storm.rs::a_seek_storm_on_an_audio_only_file_keeps_playing`.
- Dolby Vision / HDR tests are opt-in via `MVP_DV_SAMPLE` / `MVP_DV_DIR`
  (see README). Real samples are too large to commit.

## Architecture

```
mvp-subtitle   pure parsing (no internal deps, #![forbid(unsafe_code)])
mvp-platform   Windows integration only (no internal deps; stubs elsewhere)
mvp-core       FFmpeg engine, image viewer, playlist, probe, HDR  → mvp-subtitle
mvp-player     egui UI + the only binary                        → all three
```

Dependencies point one way only; `mvp-core` re-exports `mvp_subtitle as subtitle`
so callers need only depend on `mvp-core`.

- **`mvp-core/src/engine.rs` and `mvp-core/src/engine/` coexist on purpose.**
  Rust 2018 layout: `engine.rs` *is* the `engine` module and declares
  `clock` / `queue` / `workers`; `engine/` has no `mod.rs`. `engine.rs` holds the
  public API (`Engine`, `EngineConfig`, `EngineSnapshot`, `Shared`), `workers.rs`
  holds the demux/decode loops.
- **Threads:** one demuxer (`mvp-demux`), one video (`mvp-video`) and one audio
  (`mvp-audio`) worker, each 1 MiB stack; plus cpal's realtime callback and
  scoped tone-map threads. **Subtitles have no worker** — they are decoded inline
  in the demuxer loop, despite what the diagram in `engine.rs` suggests.
- **`mvp-player/src/gl/` is the only module that talks to the driver.** It holds the
  picture-adjustment pass (`picture_pass.rs`); `picture.rs` decides *what* that pass is
  told and touches no GL or egui at all, which is what makes the decisions testable
  without a window. The adjustment channel exists for **video only**:
  `PlayerApp::picture_applies` is the single predicate the menu, the shortcut, the panel,
  the per-file key and the renderer all ask, and with the sliders neutral and the
  enhancement off `picture::uniforms` returns `None`, so the pass is not in the pipeline
  at all — that, rather than a small alpha, is what "off" means.
- `mvp-player/src/app.rs` is the only place the engine, playlist, settings and
  UI state are allowed to talk to each other. `state.rs` is transient UI state
  (never persisted); `settings.rs` is the persisted document.

### Three rules the engine depends on

1. **Control never travels on the packet channels.** Seek / track changes are
   published through `Shared` (`FlushRequest`, `seek_request`) plus
   `wake_video()`; the queue has a time budget and drops when behind. Putting a
   control message on a bounded channel re-creates the deadlock where a seek
   waits behind dozens of packets. See the comments in `engine.rs` and
   `engine/queue.rs`.
2. **Never hold a lock across a driver or FFmpeg call.** That is the only reason
   `Shared::audio_sink()` exists. `ictx.seek`'s interrupt callback re-enters the
   demuxer itself, so `seek_request` must be `take()`n in a scoped block.
3. **Every packet and every `Eof` carries a `generation`.** A seek or track
   change bumps it; consumers must ignore stale generations, otherwise a stale
   EOF flushes a fresh decoder and the picture never returns.

### UI

- `ui/mod.rs::draw` is the single frame entry point and its **panel order is a
  contract**: menu bar → error banner → sidebar → transport → canvas → fullscreen
  overlay → settings → dialogs. `TopBottomPanel`/`SidePanel` shrink the available
  rect as they run, so a bottom panel declared *after* the `CentralPanel`
  reserves nothing and the canvas centres on a rect partly behind the bar.
- `canvas::draw` clears `ui.picture` at the top of every frame. A view that
  handles the pointer *before* publishing its geometry gets `None` and silently
  does nothing.
- Do not rely on egui to arbitrate between overlapping widgets; the minimap asks
  the canvas from inside the canvas's own pointer handling for this reason.

## Conventions

- **Errors:** `mvp-core` uses `thiserror` (`MediaError` + `Result` alias);
  `mvp-platform` uses `anyhow`; `mvp-subtitle` is infallible by design and must
  never panic on bad input.
- **Logging:** the `log` crate only. `mvp-player` tees to stderr and to
  `%APPDATA%\MVP-Versatile-Player\mvp.log` (bounded, ~2 MiB). Log text and all
  user-visible strings are **Chinese**; doc comments, identifiers and commit
  messages are **English**.
- **`unsafe`:** small scoped blocks with a `// SAFETY:` comment. `mvp-subtitle`
  forbids it outright.
- **Tests:** prefer an inline `#[cfg(test)] mod tests` at the bottom of the file
  over a new integration test; use `crates/*/tests/` only when the test needs a
  real FFmpeg runtime or a real device. Test names are full English sentences
  (`the_parallel_tone_map_matches_a_single_threaded_one`).
- Module-level `//!` docs are this project's design documents. When a decision is
  non-obvious or a route was measured and rejected, record it there
  (`engine.rs`, `engine/clock.rs`, `audio.rs`, `ui/surface.rs`, `layout.rs`,
  `display.rs`, `single_instance.rs` are good examples).

## Do not

- **Reintroduce glass / blur / acrylic / translucency.** `ui/glass.rs` was
  deliberately deleted and replaced by the opaque `ui/surface.rs`; the product
  owner asked for this explicitly.
- Add UI for `AspectMode::Source` — a dead variant kept only to migrate old
  `settings.json` files.
- "Clean up" unused declared dependencies; several are intentionally kept.
- Claim JXL/AVIF image support. The `image` crate is compiled without those
  decoders even though the README and `format_label` mention them.
- Add video-track switching. It is a conscious non-feature that reports itself
  instead of failing silently. (Graphical subtitles — PGS/VobSub/DVB, embedded
  and side-car — *are* supported: decoded to bitmaps in `mvp-core/src/bitmap_subtitle.rs`
  and drawn as textures by `ui/canvas.rs`; do not reintroduce an "unsupported"
  message for them.)
- Band `sws_scale` to parallelise it. It is stateful across calls; a measured
  attempt produced wrong pixels from the cut onwards. The exact route is
  `sws_frame_start` / `sws_send_slice` / `sws_receive_slice`.

## Seeing the UI

`tmp/` holds gitignored local tools for driving and capturing the running
window (`capture-ui.ps1`, `crop-ui.ps1`, `drive-ui.ps1`, `probe-px.ps1`). They
grab the **client** rect, use client coordinates, and `capture-ui.ps1` BitBlts
the screen — so a window covering the player is what gets saved. Check the
picture, not the exit code. Prefer a test whenever the behaviour is testable;
treat interactive captures as unreliable when a window or dialog moves by
itself.

Two more live there for the picture adjustments: `tmp/p1-picture-check.ps1`
(captures the screen in five settings modes — `neutral` must come back
pixel-identical to the untouched path) and `tmp/p1-snapshot-check.ps1` (measures
the mean luma of the PNG a snapshot writes, `raw` versus `baked`). Both drive the
window, so both must bring it to the foreground **and wait for a window bigger
than 200x200**: winit keeps a 16x16 helper window around, and a harness that
takes the first visible window of the process posts its keys into that one and
then reports, very convincingly, that nothing works.
